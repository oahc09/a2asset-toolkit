# Offline SDK / CLI (M1)

Install locked dependencies, then `npm run build`. The compiled CLI runs without
tsx or TypeScript transpilation at runtime. It writes one JSON object to stdout,
never prompts, and catches input errors. `--json` and `--non-interactive` are
accepted; JSON/noninteractive is also the default. Logs must stay on stderr.

```sh
node scripts/a2asset.mjs inspect examples/game-asset-request.json --json
node scripts/a2asset.mjs import ./local-pack --definition ./local-pack/definition.json --registry ./.a2asset --json
node scripts/a2asset.mjs registry list --registry ./.a2asset --kind sprite2d --json
node scripts/a2asset.mjs registry get ships.blue-falcon@1.0.0 --registry ./.a2asset --json
# Only after a real human completes the exact review record described below:
node scripts/a2asset.mjs registry approve ships.blue-falcon@1.0.0 --review-record ./review.json --registry ./.a2asset --json
node scripts/a2asset.mjs registry publish ships.blue-falcon@1.0.0 --review-record ./review.json --registry ./.a2asset --json
node scripts/a2asset.mjs registry deprecate ships.blue-falcon@1.0.0 --registry ./.a2asset --json
```

Import accepts directory or ZIP. Every supplied file is inspected; only definition-
referenced source/variant/license files enter Registry. PNG dimensions and MIME
must match declarations. Inspecting cannot invent an approval. Import metadata
must initially be imported/quarantined. No source files are rewritten. A repeated
identical import preserves existing state; new metadata at same version fails.

Review JSON is defined by `ReviewRecord` in `src/registry/index.ts`: exact asset key,
definition digest, license evidence digest, reviewer/date, source URL, author,
license expression, redistribution decision, explicit approve decision. Custom
licenses require an explicit human rights conclusion. Read `docs/m1-registry.md`.
The software checks the record's consistency, not the person's identity or legal
truth. Tests intentionally use synthetic records that must not be reused as real
asset approvals. No approval record is generated by this CLI.

Exit codes: 0 PASS; 2 input/schema/matching; 3 rights/security/state rejection;
4 processing/budget; 5 environment/I/O/unsupported command; 130 cancellation.
SIGINT/SIGTERM request cancellation; the process waits for decoder cleanup and
writes a JSON cancellation result rather than leave a partial registry commit.
A trusted private local registry root is required; it is not a shared multi-user
hostile filesystem service. No network fetch, upload, script execution from asset
packs, AI provider, or automatic download is present.
